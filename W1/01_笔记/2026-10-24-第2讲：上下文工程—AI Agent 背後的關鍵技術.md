# 第 2 講：上下文工程 (Context Engineering) — AI Agent 背後的關鍵技術

- **链接**：https://www.youtube.com/watch?v=lVdajtNpaGI&list=PLJV_el3uVTsMMGi5kbnKP5DrDHZpTX0jT&index=3
- **重点知识**：
  - 例句可以提升模型的**表现**（不是学习能力，见下面的订正）。
  - 模型的系统提示词可以很复杂。
  - 可以通过<tool></tool>标签让模型使用工具。
  - ai agent可以让模型自行选择解决方案的方法（订正见下）。
  - context engineering 需要保持记忆整洁提高模型的能力。
  - context engineering 管理记忆的方式有：选择、压缩、多Agent协作。

---

## 两处订正

**① 「例句可以提升模型的学习能力」——不准确。**
模型参数一个字都没变。这叫 **in-context learning（Few-shot）**，靠的是上下文里的模式匹配。
**安全含义**：例句也在上下文里，**所以例句同样能被注入污染**。

**② 「Agent 可以让模型自行选择解决方案」——偏了。**
Agent 的本质不是「选方法」，是 **行动 → 观察 → 再行动** 的循环。
**安全含义**：攻击面恰恰在「观察」这一步——**工具的返回值会进入上下文，而工具返回值是外部可控的**。

（`<tool></tool>` 只是课上的一种讲法。工业界更常见的是 JSON Schema 的 function calling 和 MCP。原理一样：模型吐出结构化文本，外部程序解析后执行。）

---

## 三行笔记（这才是要写的东西）

**① 一句话原理**
> 模型的「记忆」只有上下文窗口。上下文工程就是决定：**往这个窗口里放什么、按什么顺序放、什么时候清掉**。

**② 他讲浅了的地方**
> 课上讲的是「怎么让模型表现更好」，完全没讲**这些技巧同时扩大了攻击面**。工程视角和攻击视角，是同一枚硬币。

**③ 和安全的连接** ★（这段值得背下来）
> **上下文工程的三个技巧，就是三个攻击面：**
> - **选择（selection）**：选什么进上下文，谁决定？→ **检索投毒**（LLM04 / LLM08）
> - **压缩（compression）**：压缩是有损的，恶意指令可能在摘要里被「洗白」，绕过关键词检测
> - **隔离（多 Agent）**：A 的输出进入 B 的上下文 → **信任链污染**，越往下游越难追
