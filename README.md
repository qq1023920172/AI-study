# AI 应用安全 · 从零到一份评估报告

> 一个自建的 RAG + Agent 靶场，47 条攻击载荷，4,000+ 次调用，
> 以及一份 **17,749 字、可以直接交付给甲方的安全评估报告**。

**English**: A six-week, hands-on study of LLM application security — a deliberately vulnerable
RAG/Agent playground, a reproducible payload library, and a full assessment report with
risk scoring and remediation roadmap.

---

## 这是什么

不是课程笔记的搬运，是**自己搭靶场、自己打、自己修、自己写报告**的完整过程。

- 每一条结论都能指回一次实验
- 每一次判断失误都保留了（见下面「三次翻车」）
- 所有测试都在本地、针对自建环境，不含任何真实凭证

---

## 三条结论

**① 投毒的门槛在检索，不在说服。**
100 篇文档里放 1 篇（0.99%），即可改变 3/5 个敏感问题的回答；加到 20 篇，效果一点没变。
进不了检索结果的，投多少都是 0%。

**② 最常见的两类防御，实测完全无效。**
关键词黑名单被同义改写绕过（5/5）；相关性重排对投毒无影响（top-4 顺序一字未变）。
唯一经实测有效的结构性措施是**能力收窄**——把工具参数枚举化，使危险调用不存在对应接口（30/30 全挡）。

**③ 最严重的问题，恰好也是最便宜的问题。**
风险分第一（27/27）的发现是「凭证写在提示词里」，修复成本一行代码。

## 三次翻车（这是这个仓库最诚实的部分）

| 事故 | 表面现象 | 真实原因 |
|---|---|---|
| `num_predict` 被思考耗尽 | 编码类攻击 0%，像防住了 | 43% 的回答是空字符串，模型话没说完就被截断 |
| 判定器不认 `8000元` | 投毒越多效果越差 | 错判 469 条，那条"曲线"是测量误差的产物 |
| 跨会话不可复现 | 采信率 100% | 同一上下文换个时间跑，变成 20% / 40% |

> 因此本仓库只对**可稳定复现**的结论负责。详见 `W6/报告/评估报告.md` §6。

## 快速开始

```bash
python -m venv .venv
.venv\Scripts\activate            # Windows
pip install openai numpy

ollama pull qwen3:8b
ollama pull bge-m3

# 不需要模型也能跑的两个
python W1/02_代码/rag_zero.py              # 零依赖的词频检索演示
python W1/02_代码/xss_demo.html            # 浏览器打开，看 LLM05 的渲染层

# 需要 Ollama 的
python W3/02_代码/compare_retrievers.py    # 词频 vs 向量检索对照
python W5/02_代码/build_corpus.py --clean  # 生成 100 篇语料
python W5/02_代码/run.py --quick           # 投毒实验冒烟测试
```
